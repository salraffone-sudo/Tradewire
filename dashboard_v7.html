Shared Database & Sync

Connection

Paste your Supabase project URL and anon key. These are saved on this device; for a team-wide rollout, bake them into the constants at the top of the HTML file instead so everyone gets them automatically.

One-time database setup

Run this once in your Supabase project under SQL Editor:

create table if not exists projects (
  id          text primary key,
  data        jsonb not null,
  updated_at  timestamptz not null default now()
);

alter table projects enable row level security;

-- Open read/write. Anyone with the anon key can
-- read and write. Acceptable only for an internal,
-- non-public deployment.
create policy "open access" on projects
  for all using (true) with check (true);

-- Turn on live sync so edits appear for everyone
alter publication supabase_realtime add table projects;

How syncing behaves

Edits write to the shared database immediately and appear for other users within a second or two. If the connection drops, the app keeps working from a local cache and queues your changes, then flushes them automatically once it reconnects. Last write wins on conflicts.

Security note

You chose no login, so the anon key sits in this file and the access policy is open. Anyone who can reach the page can read and edit the data. That is fine behind your internal network or a private domain, but do not publish the URL. If that changes, add Supabase Auth and swap the policy for an authenticated-only rule.
